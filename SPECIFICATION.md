# Спецификация проекта TikTokGameFeed

## 1. Обзор проекта
**TikTokGameFeed** — это мобильное приложение, имитирующее ленту TikTok, но вместо видеороликов пользователи взаимодействуют с мини-играми на HTML5. Приложение позволяет листать игры свайпами вверх/вниз, играть в них прямо в ленте, а также загружать свои собственные игры.

## 2. Технический стек
*   **Платформа**: React Native (Expo SDK 52+)
*   **Язык**: TypeScript
*   **Роутинг**: Expo Router
*   **Основные библиотеки**:
    *   `react-native-webview`: Для рендеринга HTML5 игр.
    *   `expo-file-system`: Для хранения файлов игр на устройстве.
    *   `@react-native-async-storage/async-storage`: Для хранения метаданных (список игр).
    *   `react-native-pager-view` / `FlatList`: Для реализации механики ленты.

## 3. Архитектура и Структура папок

### Структура папок
*   `app/` — Маршруты и экраны (Expo Router).
    *   `(tabs)/`
        *   `index.tsx`: Экран ленты (Feed).
        *   `profile.tsx`: Экран профиля пользователя.
    *   `_layout.tsx`: Общий макет навигации.
*   `Games/` — Исходные файлы стандартных игр (для справки).
*   `src/`
    *   `services/` — Бизнес-логика.
        *   `GameStorageService.ts`: Управление файлами игр и базой данных.
    *   `types/`: TypeScript интерфейсы (например, `GameModel`).
    *   `components/`: Переиспользуемые UI компоненты.

### Модели данных
**GameModel**
```typescript
interface GameModel {
  id: string;        // Уникальный ID
  name: string;      // Название игры
  uri: string;       // Локальный путь к файлу (file://...)
  dateAdded: number; // Timestamp добавления
}
```

## 4. Ключевой функционал

### Лента игр (Game Feed)
*   **Бесконечная прокрутка**: Реализована через повторение списка игр в `FlatList` (эмуляция бесконечности).
*   **Навигация**: Вертикальный свайп переключает игры.
*   **Рендеринг**: Каждая игра загружается в `WebView`.
*   **Управление**: События прокрутки перехватываются для плавной смены слайдов.

### Профиль пользователя
*   **Список игр**: Отображает все установленные игры.
*   **Загрузка**: Пользователь может загрузить `.html` файл игры через системный пикер (`expo-document-picker`). Файл копируется во внутреннее хранилище приложения.
*   **Удаление**: Возможность удалить игру из библиотеки.

### Сервис хранения (GameStorageService)
*   **Инициализация**: Создает папку `games/` во внутреннем хранилище (`FileSystem.documentDirectory`).
*   **Seeding**: При первом запуске автоматически создает файлы стандартных игр (Falling Square, Memory Matrix) из захардкоженных строк/ассетов.
*   **Хранение**: Список игр сохраняется в `AsyncStorage` (ключ `games_list`).

## 5. Требования к играм
Игры должны быть реализованы как **единый HTML-файл** (Single File HTML).
*   Весь CSS и JS должен быть внутри `<style>` и `<script>` тегов.
*   Игра должна адаптироваться под размер экрана (`width: 100vw`, `height: 100vh`).
*   Желательно отключать дефолтные жесты браузера (`touch-action: none`), чтобы не мешать свайпам приложения (хотя приложение перехватывает свайпы, это хорошая практика).

## 6. Инструкция для Onboarding (Для разработчиков)

### Запуск проекта
```bash
npm install
npx expo start
```
*   Выберите `android` или `ios` для запуска в эмуляторе/на устройстве.

### Добавление новой стандартной игры
1.  Создайте HTML файл игры.
2.  Добавьте логику добавления в `GameStorageService.ts` в метод `seedDefaultGames`, либо реализуйте механизм копирования из папки `assets/`.
3.  Для тестирования можно просто загрузить игру через UI профиля.

### Известные особенности
*   **WebView & Swipes**: Основная сложность — конфликт жестов игры и скролла ленты. Сейчас используется кастомная обработка жестов.
*   **Storage**: Файлы хранятся в папке документов приложения, что позволяет играм работать офлайн.
