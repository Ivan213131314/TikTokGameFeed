# Спецификация Game Engine (WebView Bridge)

Этот документ описывает технический контракт и среду выполнения игр внутри приложения.

## 1. Обзор

Игры в **TikTokGameFeed** представляют собой самодостаточные HTML5 файлы, которые рендерятся внутри `react-native-webview`. Приложение не имеет доступа к внутренней логике игры (переменным, объектам), взаимодействие происходит только через postMessage и инъекцию JS.

## 2. Требования к Играм

### Формат
- **Single File**: Игра должна быть полностью упакована в один `.html` файл (CSS и JS внутри).
- **No External Assets**: Все ресурсы (картинки, звуки) должны быть либо закодированы в Base64, либо генерироваться программно (Canvas API, Web Audio API), либо загружаться по HTTPS (не рекомендуется для оффлайн работы).

### Адаптивность
- Игра должна слушать событие `window.addEventListener('resize', ...)` и адаптировать Canvas под текущие `window.innerWidth` и `window.innerHeight`.
- Мета-тег Viewport обязателен:
  ```html
  <meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no">
  ```

## 3. Bridge Контракт (Взаимодействие)

**В ТЕКУЩЕЙ РЕАЛИЗАЦИИ ОТСУТСТВУЕТ.**

На данный момент приложение (`GameContainer.tsx`) просто отображает игру в `WebView`.
Механизм двусторонней связи (`postMessage`) **не реализован**.

- Игры работают полностью изолированно.
- Счет и состояние Game Over отображаются внутри самого HTML-контента игры.
- Нативное приложение не получает данных о результате игры.

### Планируемое поведение (Not Implemented)
В будущем ожидается внедрение `window.ReactNativeWebView.postMessage` для передачи счета и управления состоянием, но в текущем коде этого нет.

## 4. Шаблон Игры (Boilerplate)

Текущий пример генерации игры находится в `src/services/GameStorageService.ts`.
Он включает внутреннюю логику рестарта и отображения очков (через DOM элементы внутри HTML), без внешней коммуникации.

```html
<!-- Фрагмент из GameStorageService.ts -->
<div id="gameOver">
    <h1>GAME OVER</h1>
    <button onclick="startGame()">RESTART</button>
</div>
```

## 5. Ограничения

- `alert()`, `confirm()`: Могут блокировать WebView или работать некорректно. Не использовать.
- `localStorage`: Внутри WebView может быть непостоянным. Для сохранения прогресса лучше использовать отправку данных в приложение (пока не реализовано сохранение стейта на сервер через postMessage).
